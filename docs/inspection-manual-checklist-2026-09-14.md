대상: R01~R07까지 변경한 개발 실행본. 아래 항목은 **수동 확인 예정**이며, 자동검사 통과와 구분한다. 수행 후 정상/이상/미확인과 사용한 LOT를 기록한다.

2026-09-22 갱신: 최종검수의 미달 사유 입력과 필수 검증을 제거했다. 계획 미달도 실제 수량으로 저장하는 기준은 [변경 기록](inspection-shortage-reason-removal-2026-09-22.md)을 따른다.

2026-09-22 후속 갱신: 검수실적의 [출고목표 초과 저장](inspection-over-target-shipment-2026-09-22.md)을 허용한다. 신규·수정·분할·최종검수에 적용하며 실제 생산 배분과 사용가능 재고 검증은 유지한다.

## 1. 시작 준비

- 입력 중인 작업을 먼저 정리한 뒤 기존 MES 창을 닫고 최신 개발용 Debug 실행본으로 다시 실행한다.
- 실행 파일: `C:/Users/jaewon/Documents/Codex/mes-v1.5/frontend-wpf/Mes.WpfClean/Mes.Wpf/Mes.Wpf/bin/Debug/net8.0-windows/Mes.Wpf.exe`
- 로그인 창 하단의 실행 환경이 **Development**인지 확인한다. 이번 서버 변경이 적용된 개발 서버를 사용한다. 새 WPF에 이전 서버를 연결하면 통합 재고 정보가 없다는 업데이트 안내가 나오는 것이 정상이다.
- 신규 저장·수량 수정은 구분 가능한 테스트용 발주·품목·LOT에서 진행한다. 저장은 실제 출고 이력과 재고를 반영하므로 기존 업무 자료를 예시 수량에 맞추지 않는다.
- 예시의 발주·출고목표·LOT 계획과 현재 재고를 먼저 확인한다. 거래처별 출고목표가 발주수량과 다를 수 있으므로 **화면의 확정 출고목표**를 기준으로 판단한다.
- 각 시나리오의 기대 재고는 다른 작업에서 같은 품목을 입출고하지 않는다는 전제다. 저장 후에는 검수 창뿐 아니라 출고·재고 조회 화면도 새로 조회한다.

기록: 확인자 __________ / 실행일시 __________ / 실행 버전 __________ / 테스트 LOT __________

## 2. 우선 확인할 화면

저장된 실적의 **상세보기**에는 `저장 후 LOT별 재고`가 표시된다. 아래 등록·수정 화면의 현재 실재고와 구분한다. [회차별 상세보기 수정 기준](inspection-saved-stock-fix-2026-09-14.md)을 함께 확인한다.

| 확인 | 조작 | 정상 결과 |
|---|---|---|
| □ | 기존재고가 있는 품목의 검수실적등록 열기 | 해당 재고 LOT 번호와 수량이 표시됨 |
| □ | 기존재고 표 확인 | `LOT 번호 / 재고수량` 두 열만 보임. 수량은 해당 LOT의 실재고 |
| □ | 신규 검수 열기 | 재고 출고수량·생산 출고수량이 모두 0에서 시작 |
| □ | 양품수량 입력 | 출고량이 임의로 바뀌지 않고 남는 양품은 재고편입수량으로 계산됨 |
| □ | 화면 구성 확인 | 출고 자동배분 선택 항목과 섹션 제목의 ‘이월 미정산’ 표시가 없음 |
| □ | 재고가 없는 품목 열기 | 재고가 0인 상태로 정상 조회되며, 양품을 재고로 편입하는 검수 저장이 가능 |

실재고가 보여도 다른 발주가 예약한 부분은 출고할 수 없다. 수정 화면에는 이미 출고한 LOT의 배정을 보여주기 위해 실재고 0인 행이 남을 수 있다. 표의 행 유무만으로 중복 재고를 판단하지 않는다.

## 3. 가장 중요한 순차 시나리오: 1차 재고편입 → 2차 출고

전제: **LOT 계획 150,000 / 확정 출고목표 150,000 / 해당 품목 기존재고 0 / 이전 출고 0**인 테스트 건. 불량·불량출고·폐기·미검수 처리수량은 모두 0으로 진행한다.

### 1차 분할검수

검수스케줄에서 해당 건을 검수시작한 뒤 검수실적등록을 연다.

| 입력 항목 | 값 |
|---|---:|
| 양품수량 | 100,000 |
| 재고 출고수량 | 0 |
| 생산 출고수량 | 0 |
| 폐기수량 | 0 |
| 재고편입수량 — 자동 계산 | **100,000** |

`분할검수 사용`을 체크하고 다음 검수일과 분할 사유를 입력한 뒤 현재 회차를 저장한다.

- □ 배분 합계 오류 없이 저장된다.
- □ 1차 검수 이력에 양품 100,000이 남는다.
- □ 다음 검수 회차가 한 번만 만들어진다.
- □ 재고 조회에서 해당 LOT 재고가 100,000 증가한다.
- □ 실제 출고된 수량은 0이며, 다음 회차 출고잔량은 150,000이다.

### 2차 검수

생성된 다음 회차를 검수시작한 뒤 검수실적등록을 연다.

- □ 1차에서 편입한 LOT와 실재고 100,000이 보인다.
- □ 신규 출고 입력값은 여전히 0이다.

아래 수량을 **직접 입력**하고 분할검수를 해제한 최종검수로 저장한다.

| 입력 항목 | 값 |
|---|---:|
| 이번 양품수량 | 50,000 |
| 재고 출고수량 — 1차 재고 사용 | 100,000 |
| 생산 출고수량 — 이번 양품 사용 | 50,000 |
| 폐기수량 | 0 |
| 재고편입수량 — 자동 계산 | **0** |

- □ 이번 회차 출고는 150,000이다.
- □ LOT 누적 양품은 150,000이다. 재고 출고 100,000을 이번 양품으로 중복 계산하지 않는다.
- □ 출고 조회의 누계는 150,000, 출고잔량은 0이다.
- □ 재고 조회의 해당 LOT 잔량은 0이다.
- □ 최종검수가 완료되고 불필요한 다음 회차가 생성되지 않는다.
- □ 창을 다시 열어도 저장된 입력값과 회차 이력이 유지된다.

결과: □ 정상 □ 이상 □ 미확인 / LOT __________ / 메모 ____________________

## 4. 기존 최종실적 수정과 중복 반영 확인

추가 확인: 2차 저장 후 **1차 상세보기**를 다시 연다. 위 시나리오에서는 생산 LOT의 저장 후 재고가 100,000, 1차 출고누계가 0, 출고잔량이 150,000으로 유지되어야 한다. 2차 상세보기에는 2차 처리 후의 재고와 출고량이 표시되어야 한다.

별도 테스트 건을 사용한다. 전제는 LOT 계획·출고목표 각 1,000, 기존재고 0이며 성적서·COA를 발행하지 않고 이후 재고를 사용하지 않은 상태다.

| 순서 | 조작 | 정상 결과 |
|---|---|---|
| □ 1 | 양품 1,000, 생산 출고 800, 재고 출고·폐기 0으로 최종 저장 | 재고편입 200, 출고 800 |
| □ 2 | 저장된 최종실적을 열어 수정 모드에서 같은 값으로 저장 | 출고 800·실재고 200이 그대로이며 중복 증가하지 않음 |
| □ 3 | 메모만 변경해 저장 | 출고·재고·양품 수량은 그대로, 메모만 반영 |
| □ 4 | 양품만 1,100으로 변경하고 생산 출고 800 유지 | 재고편입 300, 실재고는 100만 증가, 출고 800 유지 |
| □ 5 | 양품을 다시 1,000으로 변경 | 실재고가 200으로 복귀, 출고 800 유지 |
| □ 6 | 생산 출고를 800에서 850으로 변경 | 재고편입·실재고 150, 출고 누계 850 |

수량 수정으로 정정 수불 이력이 추가되는 것은 정상이다. 최종 누적 출고와 실제 재고가 변경분만큼 움직이는지 확인한다. 이미 사용하거나 다른 발주가 예약한 재고를 줄이는 수정은 차단되어야 한다.

이미 저장한 분할 회차를 임의로 다시 저장하거나, 완료된 최종검수를 분할검수로 되돌리는 동작은 현재 허용 범위가 아니다. 이 경우 차단을 오류로 판정하지 않는다. 발행된 성적서·COA가 있는 실적의 수량 수정도 정정 절차 안내가 정상이다.

결과: □ 정상 □ 이상 □ 미확인 / LOT __________ / 메모 ____________________

## 5. 수량·사유 제약

서로 독립된 테스트 건에서 진행한다. 저장 성공을 확인한 뒤 다음 항목의 숫자로 같은 건을 무조건 덮어쓰지 않는다.

| 확인 | 입력·조작 | 정상 결과 |
|---|---|---|
| □ | LOT 계획 1,000에서 양품 1,100, 생산 출고 1,000 입력. 출고목표는 1,000 이상 | 계획 초과만을 이유로 막지 않으며 남은 100은 재고편입 |
| □ | LOT 계획 1,000에서 양품 900, 출고 0으로 최종 저장 | 미달 사유 입력란·요구 안내 없이 실제 900으로 종료하고 900을 재고편입. 불량·미검수 100을 임의로 만들지 않음 |
| □ | 위 실적을 다시 열어 양품 850, 출고 0으로 수정 저장 | 사유 없이 저장되며 재고편입은 850, LOT 계획은 1,000 유지 |
| □ | 과거 미달 사유가 기록된 실적을 조회·동일값 저장 | 과거 사유는 이력에 남고 재입력을 요구하지 않음 |
| □ | 처리수량을 모두 0으로 최종 저장 시도 | 처리수량 입력 안내 후 저장 차단 |
| □ | 분할검수에서 다음 검수일 또는 분할 사유 비움 | 누락 항목 안내 후 저장 차단 |
| □ | 양품 1,000, 생산 출고 1,100 입력 | 재고편입 -100이 보이고 저장 차단. 출고를 몰래 1,000으로 바꾸지 않음 |
| □ | 재고 출고를 실제 사용 가능량보다 많이 입력 | 재고 부족 안내 후 저장 차단 |
| □ | 출고목표 1,000, 양품 1,200, 생산 출고 1,200으로 최종 저장 | 추가 확인·사유 없이 저장. 출고 1,200, 재고편입 0, 목표 1,000, 잔여 출고 0 |
| □ | 사용가능 재고 100에서 재고 출고 100 + 생산 출고 1,200 입력. 양품 1,200, 출고목표 1,000 | 실제 출고 1,300으로 저장. 재고 100 차감, 생산 전량 출고 |
| □ | 목표를 초과한 위 실적을 다시 열어 동일값 저장 또는 실제 추가 생산량을 포함해 수정 | 중복 출고 없이 동일값 유지 또는 입력한 증가분만 반영 |
| □ | 분할 회차에서 목표를 초과해 저장한 뒤 다음 회차도 출고 입력 | 잔여 목표 0이어도 수량·재고 검증이 맞으면 저장. 분할 사유·다음 검수일은 계속 필요 |
| □ | 생산 출고·폐기량을 입력한 다음 양품을 변경 | 직접 입력한 출고·폐기량 유지, 재고편입만 다시 계산 |
| □ | 불량수량을 입력하고 불량내역·유형 누락 | 필요한 불량내역 또는 유형 입력 안내 |

계획 미달로 검수를 종료해도 발주 전체가 자동으로 완료되는 것은 아니다. 예를 들어 출고목표 1,000에 실제 출고 900이면 잔여 출고 100이 남으며, 발주 완료 여부는 별도의 출고·부족종료 규칙을 따른다.

## 6. 사진·중복 저장·실패 후 재실행

| 확인 | 조작 | 정상 결과 |
|---|---|---|
| □ | 테스트 불량내역에 사진 선택·업로드 | 사진이 해당 불량내역에 연결됨 |
| □ | 저장 후 창을 다시 열어 사진 보기 | 저장한 사진이 열리며 다른 사진과 뒤바뀌지 않음 |
| □ | 저장 버튼을 빠르게 두 번 누름 | 실적·출고·다음 회차가 중복 생성되지 않음 |
| □ | 수량 또는 필수 사유 오류로 저장 실패 후 입력을 고침 | 입력값이 유지되고 수정한 값으로 다시 저장 가능 |
| □ | 사진 파일 처리에서 오류가 실제 발생한 경우 | 실패 안내가 보이고 화면이 계속 사용 가능하며 파일을 성공한 것처럼 열지 않음 |

통신 시간 초과가 발생하면 먼저 창을 다시 열거나 실적·출고 이력을 조회해 저장 여부를 확인한다. 응답만 늦게 온 상황에서 같은 작업을 반복하지 않는다. 수동검사를 위해 운영 네트워크나 서버를 일부러 중단하지 않는다.

## 7. 두 창에서의 동시 변경 — 환경이 허용할 때

권한 있는 개발용 계정과 별도 테스트 자료로 진행한다. 재고 차감·수정은 정상 메뉴를 사용한다.

- □ 동일한 최종실적을 A·B 두 창에서 연다 → A에서 변경 저장 → 재조회하지 않은 B에서 다른 값으로 저장: B의 덮어쓰기가 차단되고 재조회 안내가 나온다.
- □ 검수 창을 연 뒤 다른 작업에서 같은 품목 재고를 사용한다 → 처음 창에서 남은 재고보다 많은 출고를 저장: 최신 재고 기준으로 차단된다.
- □ 검수 창을 닫고 다시 열면 변경된 LOT 수량이 보인다. 저장 실패 후 검수 이력·재고·출고가 일부만 반영되지 않는다.

이 동시성 항목은 자동 PostgreSQL 검사에서 통과했다. 두 창으로 수행하지 못하면 정상으로 체크하지 말고 미확인으로 기록한다.

## 8. 이전 단계의 부족종료 유지 확인

테스트 발주에서 정상 메뉴로 부족종료 사유를 기록하고 부족종료를 확정한다.

- □ 발주의 일반 메모를 변경한 뒤 다시 조회해도 부족종료 결정이 유지된다.
- □ 일반 메모를 지워도 진행 상태로 임의 복귀하지 않는다.
- □ 종료 이력의 사유와 결정 기록은 일반 메모와 별도로 유지된다.

## 9. 선택: 첨부 사진과 같은 수량으로 재현

별도 테스트 건에서 확정 출고목표 600,000, 계획 535,000, 출고 가능한 기존재고 65,000, 이전 검수·출고 0을 전제로 한다. 실제 불량유형과 불량내역을 함께 등록한다.

| 양품 | 432,000 |
| 불량 | 10,456 |
| 불량출고·폐기·미검수 처리 | 0 |
| 재고 출고 | 65,000 |
| 생산 출고 | 432,000 |
| 재고편입 — 자동 계산 | 0 |

`분할검수 사용`을 체크하고 다음 검수일·사유를 입력한 뒤 저장한다.

- □ 처리수량은 442,456, 이번 출고는 497,000이다.
- □ 남은 출고목표는 103,000이다.
- □ 이전 사진의 배분 합계 오류 없이 저장되고 다음 회차가 하나 생성된다.

기존재고 65,000이 보인다는 이유만으로 자동 출고되어서는 안 된다. 이번 검사는 위 출고량을 사용자가 직접 입력한 경우다.

## 10. 이상 발생 시 남길 내용

아래 정보를 함께 기록하면 재현 대상을 빠르게 좁힐 수 있다.

- 확인표 번호, 개발/운영 구분, 실행 버전과 발생 시각
- LOT 번호와 검수 회차, 신규 저장인지 기존 실적 수정인지
- 양품·불량출고·불량·미검수 처리·재고 출고·생산 출고·폐기·재고편입 수량
- 예상 결과와 실제 결과, 오류 문구·요청 ID 또는 오류 ID
- 저장 전후의 검수·출고·재고 화면

기록 예시: `3번 / 개발 / LOT ____ / 2차 / 양품 50,000·재고출고 100,000·생산출고 50,000 / 예상 출고 150,000 / 실제 ____`.

핵심 판정은 3번의 분할검수 전체 흐름, 4번의 수정 차이 반영, 5번의 잘못된 저장 차단이다. 미확인 항목을 통과로 표시하지 않는다. 이번 문서 작성에서는 코드·DB 변경이나 실제 업무 저장을 수행하지 않았다.
