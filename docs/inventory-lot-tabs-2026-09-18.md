# 재고관리 — 좌측 LOT 재고현황·우측 재고이력관리

구현 및 검증일: 2026-09-18. 개발 소스와 Debug 빌드에 반영했다. 개발 업무 DB 및 운영 데이터는 변경하지 않았다. 이후 점검에서 발견한 합계·선택·안내문 문제도 수정했으며, 최신 결과는 [후속 수정 기록](inspection-inventory-review-fixes-2026-09-18.md)을 기준으로 한다.

## 사용 순서

1. 생산관리 → 재고관리에서 품목명 또는 품목코드로 조회한다. 거래처 컬럼과 거래처 검색은 제거했다.
2. 상단 품목을 선택하면 하단 왼쪽 **재고현황**에 해당 품목의 LOT 번호, 현재 재고수량, LOT 재고의 최종수정일시가 표시된다.
3. LOT를 선택한 후 **상세보기**를 누르면 오른쪽 **재고이력관리**에 해당 LOT의 입·출고 이력이 표시된다. LOT 목록에서 Enter 키로도 열 수 있다. 왼쪽 목록과 오른쪽 이력은 항상 함께 보이며 가운데 구분선을 끌어 너비를 조절할 수 있다.
4. 오른쪽에서 선택 LOT의 입·출고 이력을 기간·구분으로 조회한다. 날짜를 비우면 전체 기간이며, 한국시간 기준으로 검색한다. 상세보기를 열기 전에는 이력 검색을 비활성화한다.
5. 다른 LOT를 선택하면 이전 이력을 즉시 지우고 **상세보기** 안내를 표시한다. 새 LOT의 상세보기를 누르면 새 이력을 조회한다. 이전 요청이 늦게 도착해도 다른 LOT의 이력을 표시하지 않는다. 품목을 바꾸면 LOT·이력·상세 검색조건을 초기화한다.
6. 재고가 소진된 품목이나 LOT는 상단 **재고 0 포함**을 체크한 뒤 조회한다. 재고원장이 아직 없는 신규 품목은 이 목록의 대상이 아니다.

품목은 기존 100건, LOT 및 이력은 각각 50건씩 조회한다. LOT의 조회 합계는 현재 페이지가 아닌 검색조건 전체의 합계다.

## 품목 연속 선택 시 조회 지연 — 후속 반영

- 상단 품목을 선택하면 250ms 대기 후 해당 품목의 LOT 재고를 조회한다. 그 사이 다른 품목을 선택하면 이전 대기 요청은 서버로 보내지 않는다. 마지막 선택부터 다시 250ms를 기다린다.
- 품목이 바뀌는 즉시 이전 LOT와 이력을 비우고 조회 준비 상태를 표시한다. 대기 중에는 이전 LOT의 상세보기·조정을 실행할 수 없다.
- 같은 품목을 다시 클릭하는 동작에는 추가 요청이 없다. 초기화나 선택 해제는 대기 중인 조회를 무효화한다. 사용자가 상단 목록을 직접 재조회하면 해당 조회 결과에 따라 LOT를 즉시 갱신하고 기존 대기 요청은 중복 전송하지 않는다.
- 이미 서버에 전송된 요청을 취소하는 변경은 아니다. 이전 품목의 늦은 응답은 기존 요청 순번 검증으로 버린다. 캐시나 서버 쿼리는 변경하지 않았다.
- 변경 파일: 재고 화면 `ViewModels/InventoryPageViewModel.cs`, `frontend-wpf/tests/InventoryRegression/Program.cs`, `docs/project-operations.md`, 본 문서.
- 수정 전 검증에서 즉시 요청이 발생하는 것을 재현했다. 수정 후 **20번 연속 선택 → 마지막 품목 LOT 조회 1회**를 합성 API로 확인했다. 선택 변경·선택 해제·초기화·직접 재조회·실패 후 재시도·늦은 응답과 기존 이력·조정·화면 바인딩을 포함하여 **46개 검증 통과**.
- WPF 빌드 **오류 0, 경고 0**. 실행 중인 개발 MES가 기존 출력 파일을 사용하여 일반 빌드는 잠금으로 실패했고, 프로그램을 종료하지 않고 `.tmp/inventory-debounce-build/`에 별도 빌드하여 검증했다. 현재 실행 중인 화면에는 변경이 즉시 반영되지 않는다. 해당 폴더의 `Mes.Wpf.exe`가 검증한 개발 빌드다.
- 백엔드·DB 변경이 없어 서버 테스트는 이번 후속 변경에서 재실행하지 않았다. 운영 서버의 실제 CPU·동시 사용자 부하 및 대량 데이터 응답시간은 측정하지 않았으며, 운영 배포도 수행하지 않았다. 250ms 이후 이미 시작한 요청은 서버에서 계속 처리될 수 있다.
- 수동 확인: 새 개발 빌드에서 품목을 연속 선택한 뒤 마지막 품목의 재고만 표시되는지, 대기 중 초기화하면 결과가 다시 나타나지 않는지, LOT 상세보기·재고조정 진입이 정상인지 확인한다.

## 목록 정렬·검색·최종수정일시

- 품목 목록, LOT 목록, 입출고 이력의 제목과 셀을 가로·세로 중앙정렬했다. 숫자의 기존 우측 정렬도 제거했다.
- 상단 컬럼은 **품목코드 / 품목명 / 현재 재고수량 / 단위 / 최종수정일시** 순서다. LOT 목록은 **LOT 번호 / 재고수량 / 최종수정일시**다.
- 거래처 표시 및 검색용 수주·거래처 조회와 응답 필드도 삭제했다. 품목명·품목코드로 검색하며 수주 연결이 없는 기초재고도 그대로 조회한다. 긴 품목명은 마우스를 올리면 전체 내용을 확인할 수 있다.
- 최종수정일시는 품목 재고 원장과 LOT 재고 원장의 `updated_at`이다. 품목 마스터 변경일이나 가장 최근 검수일이 아니며, 한국시간으로 표시한다. 상단은 `yyyy-MM-dd HH:mm:ss`, 좁은 하단 LOT·이력 일시 컬럼은 날짜와 시간을 두 줄로 표시한다.
- LOT 재조회 시 품목 수량·수정일시, 이력 재조회 시 선택 LOT 수량·수정일시를 함께 갱신한다. 미확인 날짜는 **—**로 표시한다.

현재 좌우 배치 변경에서는 탭 상태와 탭 복귀 명령을 삭제하고, 선택 LOT의 상세보기 상태만 관리한다. 날짜·구분·페이지 조회, 0 재고 포함, LOT별 조정 및 정합성 안내는 유지한다.

## 표시 수량의 의미

| 항목 | 의미 |
|---|---|
| 상단 현재 재고수량 | 품목 전체의 현재 실재고 |
| 재고현황의 현재 재고수량 | 해당 원래 재고 LOT의 현재 실재고. 예약된 수량도 포함 |
| 이력 상단 현재 재고 | 이력 조회 시점의 해당 LOT 잔액 |
| 입고수량·출고수량 | 해당 처리에서 실제 재고가 변한 양 |
| 처리 후 재고 | 해당 이력이 반영된 직후 그 LOT의 잔액 |
| 입고 정정·출고 정정 | 이전 처리의 증감 정정. 취소되는 양은 해당 입고/출고 열의 음수로 표시 |

- 같은 품목이어도 원래 LOT가 다르면 수량과 이력을 합쳐 표시하지 않는다.
- 이력은 최신 **처리 순서**로 정렬한다. 같은 시각이거나 일시가 소급된 이력도 내부 처리 순번으로 잔액을 계산한다.
- 기간·구분·페이지 검색을 하기 전에 전체 LOT 이력의 누계를 계산하므로 검색조건을 바꿔도 같은 이력의 처리 후 재고는 변하지 않는다.
- 기존 이력의 합계와 현재 LOT 재고가 다르면 잔액을 추정하지 않고 **확인불가**와 경고를 표시한다. LOT 연결이 없는 과거 이력은 번호 문자열만으로 임의 연결하지 않는다.
- 품목 전체 재고와 LOT 합계가 다르면 재고현황에 정합성 점검 안내를 표시한다.
- 검수의 생산 입고량과 화면의 재고편입량은 다르다. 원장에는 검수 생산분의 입고와 해당 생산분의 출고를 각각 기록한다. 검수 화면의 재고편입은 생산 출고·폐기를 반영한 잔여수량이다. 입고와 출고가 각각 보이는 것은 정상적인 수불 기록이며, 동일 LOT의 순증감으로 잔액을 확인한다.

## 분할검수 사례 검증

아래는 운영 DB를 고친 결과가 아니라 동일 수량으로 만든 합성 데이터의 검증 결과다.

| 시점 | 기존 LOT | 생산 LOT | 전체 재고 |
|---|---:|---:|---:|
| 기존 재고 | 39,500 | 0 | 39,500 |
| 1차 양품 100,000, 출고 없이 저장 | 39,500 | 100,000 | 139,500 |
| 2차 양품 300,000, 재고출고 139,500 + 생산출고 160,500 | 0 | 139,500 | 139,500 |

2차는 새로 검수한 300,000장이다. 기존 LOT 39,500장과 1차 생산분 100,000장이 재고에서 출고되고, 2차의 잔여 139,500장이 생산 LOT에 편입된다. 기존 LOT 이력은 39,500 입고 → 39,500 출고 → 잔액 0으로 조회된다.

생산 LOT의 원장에는 1차 입고 100,000 → 2차 입고 300,000 → 기존 재고 출고 100,000 → 이번 생산 출고 160,500이 기록되어 139,500이 남는다. 이는 이전 LOT의 39,500장을 생산 LOT로 옮긴 기록이 아니다.

## 재고조정

- 선택한 LOT에만 증감하며, 다른 LOT에서 대신 차감하지 않는다.
- 양의 정수 수량과 1,000자 이내의 사유를 입력하고 대상 LOT·수량을 확인한 뒤 저장한다.
- 감소 가능한 수량은 해당 LOT의 미예약 수량까지다. 화면의 실재고 전체가 감소 가능한 수량이라는 뜻은 아니다.
- 서버에서 품목과 LOT의 소속을 다시 검증하고, 기존 품목 잠금과 예약 보호 아래 원장·LOT·이력을 같은 트랜잭션으로 반영한다.
- 저장 중에는 중복 저장과 창 닫기를 막는다. 실패하면 입력을 유지한다. 응답이 불명확할 때는 이력을 먼저 조회하며 자동 재전송하지 않는다.
- 기초재고등록과 정합성점검은 상단 **관리기능**에서 실행한다.
- 과거 인라인 증감 입력과 사용되지 않는 `InventoryEditModel`은 삭제했다. 기존 외부 호출 호환성을 위한 서버의 품목 단위 조정 경로는 유지하지만 새 화면은 호출하지 않는다.
- 구 품목 단위 조정 경로에도 신규 LOT 조정과 동일하게 사유 1~1,000자와 공백 금지를 적용한다. 사유가 없는 요청은 422로 거부하며 재고를 변경하지 않는다.

## API 및 유지보수

| 경로 | 변경 |
|---|---|
| GET /inventories | include_zero 추가. 기본값 false. q는 품목코드·품목명을 검색하며 재고 updated_at 반환. 거래처 응답 필드 삭제 |
| GET /inventories/{product_id}/lots | 품목 소속 LOT 조회, 검색·0 포함·페이지, 품목 합계와 LOT 합계 불일치 안내. product_updated_at 및 각 LOT updated_at 반환 |

| POST /inventories/{product_id}/lots/{lot_id}/adjust?direction=IN 또는 OUT | 선택 LOT만 조정. qty와 memo 필수 |

- 목록 응답은 LOT 식별자를 포함한다. WPF는 요청한 품목·LOT와 다른 응답을 표시하지 않는다. 늦게 도착한 이전 선택의 응답도 버린다.
- 새 LOT 조정은 별도 경로를 사용하므로 구버전 서버가 LOT 필드를 무시하고 다른 LOT를 FIFO 차감할 수 없다.
- 서버의 기존 INVENTORIES.VIEW / INVENTORIES.WRITE 권한 검증을 그대로 적용한다.
- 현재 수량과 이력 합계는 동일한 읽기 전용 스냅샷에서 조회한다. 기존 검수 읽기 세션 도우미를 재사용했다.
- 새 WPF는 이력 조회에 현재 LOT 페이지와 적용된 검색조건을 함께 보내고, stock_snapshot의 수량·합계·수정일시를 한 번에 반영한다. 입력만 하고 조회하지 않은 LOT 검색조건은 사용하지 않는다. 0 재고 제외 등으로 선택 LOT가 목록에서 사라지면 상세보기를 닫는다.
- LOT 재조회 중 바꾼 선택·선택 해제는 응답 적용 시 유지한다. 새 품목 또는 새 LOT 조회가 시작되면 이전 이력 응답을 무효화하며, 이전 안내문도 다시 표시하지 않는다. stock_snapshot이 없는 구 서버의 응답은 부분 반영하지 않고 서버 버전 확인을 안내한다.
- DB 구조와 의존성은 추가하지 않았다. 기존 LOT 인덱스를 사용한다.

## 미실행 항목·남은 위험·수동 확인

- 운영 배포, 운영/개발 업무 데이터 저장 테스트는 수행하지 않았다. 이번 검증은 업무 자료를 변경하지 않는 합성 데이터에서 수행했다.
- 실운영 자료량에서의 응답시간, 실제 모니터 배율별 화면, 사용자 계정별 전체 메뉴 이동은 현장에서 확인해야 한다.
- 기존 원장의 누락이나 잘못된 LOT 연결 자체를 자동 복구하는 변경은 아니다. 경고가 있는 자료는 원본 검수·출고 기록과 대조 후 별도로 정리해야 한다.
- **서버를 먼저 업데이트·재시작하고 새 WPF를 배포해야 한다.** 새 화면과 이전 서버의 혼용은 지원하지 않는다. 이번 변경 자체에는 신규 마이그레이션이 없지만, 함께 배포하는 이전 미배포 변경의 마이그레이션 여부는 별도 릴리스 점검 대상이다.

수동 확인 순서:

1. 개발 프로그램을 다시 실행하고 생산관리 → 재고관리에서 품목을 선택한다.
2. 거래처 컬럼이 없고 품목코드·품목명으로 검색되는지 확인한다. 셀의 가로·세로 중앙정렬과 한국시간 최종수정일시를 확인한다. 하단 왼쪽 LOT 목록은 번호·수량·최종수정일시 세 열이어야 한다.
3. 재고 0 포함을 체크하고 조회하여 소진된 LOT를 선택할 수 있는지 확인한다.
4. LOT 선택 후 **상세보기**를 눌러 오른쪽의 LOT 번호, 입출고 수량과 처리 후 재고를 확인한다. 왼쪽 목록이 함께 보여야 하며, 기간/구분을 바꿔도 같은 이력의 잔액이 유지되어야 한다.
5. 다른 LOT를 선택하면 오른쪽 이전 이력이 사라지고 상세보기 안내가 표시되어야 한다. 새 상세보기를 누르면 그 LOT 이력만 나와야 한다. 다른 품목을 선택하면 이전 LOT·이력·상세 검색조건이 초기화되어야 한다. 구분선으로 양쪽 너비를 조절하고 LOT 목록 Enter 키도 확인한다.
6. 테스트용 LOT에서만 재고조정을 열어 대상 LOT와 필수 사유를 확인한다. 예약수량을 침범하는 감소는 거부되고 다른 LOT는 변하지 않아야 한다.
7. 관리기능의 기초재고등록·정합성점검 진입을 확인한다.
