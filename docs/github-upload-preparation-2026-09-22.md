# GitHub 업로드 및 서버 배포 준비 — 2026-09-22

현재 개발 컴퓨터에 누적된 변경을 GitHub에 보관하고 다음 서버 배포 검토의 기준으로 사용한다. 대상 저장소는 `https://github.com/ycpark85/mes-v1.5.git`, 작업 브랜치는 `codex/prepare-server-deployment-20260922`, 시작 커밋은 `ae892e8`이다. 업로드 준비 시 로컬 main과 원격 main이 같은 커밋임을 확인했다.

## 업로드 범위

- 검수실적의 회차 정산·재고·이월·수정 이력과 동시 수정 보호, 저장 당시 재고 조회.
- 최종검수의 미달 사유 요구 제거, 검수 출고목표 초과 저장 허용.
- LOT별 재고 조회·수불·조정 화면, 발주의 명시적 부족종결 상태와 이력.
- 클라이언트·서버 호환성 확인, API 오류 표시와 진단, 배포 검증 스크립트.
- 관련 회귀 테스트, DB 마이그레이션 파일, 운영구조·상세 검토 문서.

이전 작업에서 남아 있던 개발 변경을 포함한다. 이번 업로드 요청을 처리하면서 애플리케이션 기능을 추가 변경하지 않았다. 변경 파일의 전체 목록은 이 브랜치의 커밋 변경 내역으로 확인한다.

업로드 정리를 위해 `.gitignore`에 루트 `.tmp`와 `.pytest_cache` 제외 규칙을 추가하고, 과거에 추적되던 Python 캐시 41개는 Git 추적만 해제한다. 개발 PC의 캐시 파일은 삭제하지 않는다. `.env`, 가상환경, DB 백업·업무 첨부자료, 임시 진단자료와 빌드 산출물은 업로드 대상이 아니다.

## 검증 결과

- 전체 백엔드: **390개 통과, 8개 건너뜀, 하위 검사 68개 통과**. `python -B -m pytest tests -q -p no:cacheprovider`로 실행했으며, 전용 PostgreSQL 연결은 사용하지 않았다.
- WPF 솔루션: **Debug·Release 모두 빌드 성공, 각각 오류 0·경고 0**. 내부 MES와 협력사 WPF 프로젝트를 포함한다.
- API 회귀 검사: **34개 통과**.
- 재고 화면 회귀 검사: **57개 통과**.
- 검수 화면 회귀 검사: 직전 출고목표 초과 변경 검증의 **83개 통과** 결과를 유지한다. 이후 해당 기능 코드는 추가 변경하지 않았다.
- 업로드 후보의 자격증명 패턴과 파일 구성을 확인했다. 감지된 문자열 한 곳은 비밀번호 변경 API 경로 상수였다. 비밀 설정 파일은 제외했다.

개발용 MES 프로그램이 실행 중이어서 기존 Debug 실행 파일 복사가 처음에는 실패했다. 프로그램을 종료하지 않고 프로젝트별 `bin/GitHubUpload/Debug`와 `bin/GitHubUpload/Release`로 출력 경로를 분리해 빌드를 완료했다. 이 출력은 검증용이며 서버에 복사하지 않았다.

## 남은 서버 배포 검증

- 건너뛴 8개 중 7개는 전용 PostgreSQL의 동시성·조회 격리·마이그레이션·재고 흐름 검증, 1개는 테스트 사용자 권한상 심볼릭 링크 생성 검증이다.
- 누적 변경에는 `5a6b7c8d9e0f`와 `6b7c8d9e0f1a` 마이그레이션이 포함된다. GitHub 업로드는 DB 적용이 아니다. 운영의 현재 버전·스키마·미커밋 변경, 백업과 복구 절차를 확인한 뒤 별도 적용 계획이 필요하다.
- 실제 운영자료를 사용한 저장, 운영 프로그램 화면 확인, 운영 서비스 재시작·마이그레이션·배포는 실행하지 않았다.
- 프로젝트 운영 기준에 따라 검증된 변경을 main에 병합한 뒤 운영 PC가 main을 fast-forward로 받는 순서를 따른다. 이번 업로드는 개발 브랜치에 한정한다.
